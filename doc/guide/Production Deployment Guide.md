## 1. Prerequisites

| Requirement | Minimum             | Recommended                                       |
| ----------- | ------------------- | ------------------------------------------------- |
| **CPU**     | 4 cores             | 16+ cores (pipeline parallelism)                  |
| **RAM**     | 8 GB                | 32+ GB (DESeq2 / large genomes)                   |
| **Disk**    | 100 GB SSD          | 500 GB+ NVMe (reference genomes are ~44 GB alone) |
| **OS**      | Ubuntu 22.04 LTS    | Ubuntu 24.04 LTS                                  |
| **Network** | Public IP or domain | Domain with DNS configured                        |

The pipeline is CPU- and memory-intensive. HISAT2 alignment, featureCounts, DESeq2, and HISAT2 index building all scale with thread count. The more cores available, the faster jobs complete.

## 3. Conda Environment Setup

RNAseek depends on both R/Bioconductor packages and Python scientific packages. Conda manages both ecosystems under a single environment.

```bash
# Install Miniconda (if not already present)
wget https://repo.anaconda.com/miniconda/Miniconda3-latest-Linux-x86_64.sh
bash Miniconda3-latest-Linux-x86_64.sh -b -p /opt/miniconda3
eval "$(/opt/miniconda3/bin/conda shell.bash hook)"
conda init bash
source ~/.bashrc

# Create the rnaseek environment from the lock file
cd /opt/rnaseek
conda env create -f environment.yml

# Activate and install pip packages
conda activate rnaseek
pip install -r requirements.txt
```

**Important:** The `environment.yml` installs conda-channel packages (R 4.3, Bioconductor packages like DESeq2/SVA, and bioinformatics CLI tools like HISAT2/SAMtools/Trimmomatic/FastQC/Subread). The `requirements.txt` installs the Python-only packages (Django, Celery, scientific Python, etc.) via pip inside the conda environment.

Verify the critical tools are on `$PATH`:

```bash
conda activate rnaseek
which hisat2 && which samtools && which featureCounts && which fastqc && which trimmomatic
python -c "import django; print(django.get_version())"
python -c "import rpy2.robjects as ro; print(ro.r('R.version.string')[0])"
```

## 4. Project Files

```bash
# Clone the repository
sudo mkdir -p /opt/rnaseek
sudo chown $USER:$USER /opt/rnaseek
git clone <your-repo-url> /opt/rnaseek
cd /opt/rnaseek
```

**Directory layout in production:**

```
/opt/rnaseek/              ← Application code (git repo)
/opt/rnaseek/staticfiles/  ← Collected static files (generated by collectstatic)
/data/rnaseek/media/       ← User uploads & pipeline outputs (MEDIA_ROOT)
```

Create the media directory:

```bash
sudo mkdir -p /data/rnaseek/media/sessions
sudo chown -R $USER:$USER /data/rnaseek/media
```

> **Why a separate `/data/` mount?** The `media/` directory stores user-uploaded FASTQ files (often multi-GB), pipeline intermediates (BAM, CRAM), and outputs. Keeping it on a separate partition or NFS mount prevents the root disk from filling up and makes backups/resizing independent of the application.

## 5. PostgreSQL Database

SQLite cannot handle concurrent writes from multiple Celery workers — PostgreSQL is required in production.

```bash
# Start and enable PostgreSQL
sudo systemctl enable postgresql
sudo systemctl start postgresql

# Create database and user
sudo -u postgres psql <<SQL
CREATE USER rnaseek WITH PASSWORD '<strong-password>';
CREATE DATABASE rnaseek OWNER rnaseek;
GRANT ALL PRIVILEGES ON DATABASE rnaseek TO rnaseek;
\q
SQL
```

**Security notes:**
- Use a strong, randomly generated password (e.g., `openssl rand -base64 32`).
- PostgreSQL listens on `127.0.0.1:5432` by default — this is correct for a single-server deployment. If the DB is on a separate host, configure `pg_hba.conf` accordingly.

## 6. Redis

Redis serves two roles in RNAseek:
1. **Celery broker** — Distributes pipeline tasks to worker processes.
2. **Django Channels layer** — Routes WebSocket messages for real-time progress updates.

```bash
sudo systemctl enable redis-server
sudo systemctl start redis-server

# Verify
redis-cli ping
# → PONG
```

Default config (`127.0.0.1:6379`) works for single-server setups. For multi-server, bind to the private network interface and set a password in `/etc/redis/redis.conf`.

## 7. Environment Variables

RNAseek reads all configuration from environment variables. The `.env.prod` file in the repo is a template — copy it and fill in real values:

```bash
cd /opt/rnaseek
cp .env.prod .env
nano .env
```

The `.env` file should contain:

```ini
# ── Core ──
RNASEEK_ENV=production
DJANGO_SECRET_KEY=<generate-with: python -c "from django.core.management.utils import get_random_secret_key; print(get_random_secret_key())">
DJANGO_ALLOWED_HOSTS=your-domain.com,www.your-domain.com

# ── PostgreSQL ──
DB_NAME=rnaseek
DB_USER=rnaseek
DB_PASSWORD=<the-password-from-step-5>
DB_HOST=127.0.0.1
DB_PORT=5432

# ── Redis ──
CELERY_BROKER_URL=redis://127.0.0.1:6379/0
CELERY_RESULT_BACKEND=redis://127.0.0.1:6379/0
REDIS_URL=redis://127.0.0.1:6379/0

# ── File Storage ──
MEDIA_ROOT=/data/rnaseek/media
```

**How the settings module uses these:**
- `RNASEEK_ENV=production` flips `IS_PRODUCTION=True`, enabling PostgreSQL, `DEBUG=False`, HSTS headers, SSL redirect, and secure cookies.
- `DJANGO_SECRET_KEY` — Cryptographically signs sessions/cookies. Must be unique and secret per deployment.
- `DJANGO_ALLOWED_HOSTS` — Django rejects HTTP requests whose `Host` header doesn't match this list. Set to your actual domain(s).

Generate a secret key:

```bash
cd /opt/rnaseek && conda activate rnaseek
python -c "from django.core.management.utils import get_random_secret_key; print(get_random_secret_key())"
```

## 9. Static Files

RNAseek uses **WhiteNoise** to serve static files (CSS, JS, images) directly from the ASGI server without needing Nginx to handle them. This simplifies the deployment and ensures cache-busting via hashed filenames.

```bash
python manage.py collectstatic --noinput
```

This copies all static files from `pipeline/static/` into `staticfiles/` and generates compressed, content-hashed versions (e.g., `global.a1b2c3d4.css`). WhiteNoise serves them with far-future `Cache-Control` headers for optimal performance.

## 10. Reference Genomes

The pre-built HISAT2 indexes (~44 GB total for all 11 organisms) are **NOT stored in Git** — they must be transferred separately to the production server.

```bash
# Option A: rsync from dev machine
rsync -avz --progress \
    /path/to/dev/rnaseek/pipeline/reference_genomes/ \
    user@production-server:/opt/rnaseek/pipeline/reference_genomes/

# Option B: Download and rebuild (takes hours for large genomes)
# See the reference genome scripts in the project docs.
```

**What's in reference_genomes/:**
Each organism subdirectory contains:
- `.fa` — Genome FASTA sequence (used by samtools for CRAM→BAM conversion)
- `.gtf` — Gene annotation (used by featureCounts for quantification)
- `.1.ht2` through `.8.ht2` — Pre-built HISAT2 index files (used for read alignment)

## 11. Daphne (ASGI Server)

RNAseek uses **Daphne** (the Django Channels ASGI server) instead of Gunicorn because the application requires WebSocket support for real-time pipeline progress updates. Gunicorn only handles HTTP; Daphne handles both HTTP and WebSocket connections.

**How it fits in the stack:**
```
Client → Nginx (port 80/443) → Daphne (port 8099) → Django/Channels
```

Test that Daphne starts correctly:

```bash
cd /opt/rnaseek && conda activate rnaseek
daphne -b 127.0.0.1 -p 8099 config.asgi:application
```

You should see:

```
Starting server at tcp:port=8099:interface=127.0.0.1
HTTP/2 support not enabled (install the http2 and tls Twisted extras)
Configuring endpoint tcp:port=8099:interface=127.0.0.1
Listening on TCP address 127.0.0.1:8099
```

> **Bind to 127.0.0.1**, not `0.0.0.0`. Nginx will proxy to Daphne on localhost — there's no reason for Daphne to be directly accessible from the internet.

## 12. Celery Worker

Celery processes the bioinformatics pipeline tasks in the background. Each submitted analysis job is picked up by a Celery worker, which runs the full pipeline (FastQC → Trimmomatic → HISAT2 → featureCounts → DESeq2).

```bash
cd /opt/rnaseek && conda activate rnaseek

# Test start (foreground)
celery -A config worker \
    --loglevel=info \
    --concurrency=2 \
    --pool=prefork
```

**Concurrency considerations:**
- Each pipeline task is CPU-intensive (HISAT2 uses multiple threads internally).
- `--concurrency=2` means at most 2 pipeline jobs run simultaneously.
- Inside each job, tools like HISAT2 and featureCounts use multiple threads (auto-detected from `os.cpu_count()`).
- **Rule of thumb:** Set `--concurrency` to `floor(total_cores / threads_per_tool)`. On a 16-core machine with HISAT2 using 8 threads per sample, use `--concurrency=2`.

> **Do NOT set high concurrency** (e.g., 16) — each pipeline task already internally parallelizes across multiple threads. High Celery concurrency would oversubscribe the CPU and slow everything down.

## 13. Nginx Reverse Proxy

Nginx sits in front of Daphne, handling:
- SSL termination (HTTPS)
- Static file serving (optional, WhiteNoise handles this too)
- WebSocket upgrade (`Upgrade: websocket` headers)
- Request buffering and rate limiting

```bash
sudo nano /etc/nginx/sites-available/rnaseek
```

```nginx
upstream daphne {
    server 127.0.0.1:8099;
}

server {
    listen 80;
    server_name your-domain.com www.your-domain.com;

    # Redirect all HTTP → HTTPS
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name your-domain.com www.your-domain.com;

    # SSL (certbot will fill these in — see Step 14)
    ssl_certificate /etc/letsencrypt/live/your-domain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/your-domain.com/privkey.pem;
    include /etc/letsencrypt/options-ssl-nginx.conf;
    ssl_dhparam /etc/letsencrypt/ssl-dhparams.pem;

    # Max upload size — FASTQ files can be multi-GB
    client_max_body_size 50G;

    # Timeouts for long-running uploads
    proxy_read_timeout 600s;
    proxy_connect_timeout 60s;
    proxy_send_timeout 600s;

    # ── HTTP requests → Daphne ──
    location / {
        proxy_pass http://daphne;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # ── WebSocket requests → Daphne ──
    location /ws/ {
        proxy_pass http://daphne;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # WebSockets need long timeouts
        proxy_read_timeout 86400s;
        proxy_send_timeout 86400s;
    }

    # ── (Optional) Serve media files directly via Nginx ──
    # Only enable if you need to serve large pipeline output files
    # outside of Django's download view.
    # location /media/ {
    #     alias /data/rnaseek/media/;
    #     internal;  # Only allow X-Accel-Redirect from Django
    # }
}
```

Enable the site:

```bash
sudo ln -s /etc/nginx/sites-available/rnaseek /etc/nginx/sites-enabled/
sudo rm -f /etc/nginx/sites-enabled/default   # Remove default site
sudo nginx -t                                   # Test config
sudo systemctl reload nginx
```

## 14. SSL / HTTPS

Use Let's Encrypt (free) via Certbot:

```bash
sudo certbot --nginx -d your-domain.com -d www.your-domain.com
```

Certbot will:
1. Verify domain ownership via an HTTP challenge.
2. Generate and install SSL certificates.
3. Auto-modify the Nginx config with certificate paths.
4. Set up auto-renewal via a systemd timer.

Verify auto-renewal:

```bash
sudo certbot renew --dry-run
```

## 15. Systemd Services

Create systemd unit files so Daphne and Celery start on boot and restart on failure.

### 15a. Daphne Service

```bash
sudo nano /etc/systemd/system/rnaseek-daphne.service
```

```ini
[Unit]
Description=RNAseek Daphne ASGI Server
After=network.target postgresql.service redis.service

[Service]
Type=simple
User=rnaseek
Group=rnaseek
WorkingDirectory=/opt/rnaseek
EnvironmentFile=/opt/rnaseek/.env

ExecStart=/opt/miniconda3/envs/rnaseek/bin/daphne \
    -b 127.0.0.1 \
    -p 8099 \
    config.asgi:application

Restart=on-failure
RestartSec=5

# Hardening
NoNewPrivileges=yes
ProtectSystem=strict
ReadWritePaths=/data/rnaseek/media /opt/rnaseek/db.sqlite3
PrivateTmp=yes

[Install]
WantedBy=multi-user.target
```

### 15b. Celery Worker Service

```bash
sudo nano /etc/systemd/system/rnaseek-celery.service
```

```ini
[Unit]
Description=RNAseek Celery Worker
After=network.target redis.service

[Service]
Type=simple
User=rnaseek
Group=rnaseek
WorkingDirectory=/opt/rnaseek
EnvironmentFile=/opt/rnaseek/.env

ExecStart=/opt/miniconda3/envs/rnaseek/bin/celery \
    -A config worker \
    --loglevel=info \
    --concurrency=2 \
    --pool=prefork

Restart=on-failure
RestartSec=10

# Pipeline tasks can run for hours (e.g., HISAT2 index build for human genome)
TimeoutStopSec=3600

# Hardening
NoNewPrivileges=yes
ProtectSystem=strict
ReadWritePaths=/data/rnaseek/media /opt/rnaseek /tmp
PrivateTmp=yes

[Install]
WantedBy=multi-user.target
```

### Enable and start:

```bash
# Create a dedicated system user (no login shell)
sudo useradd --system --create-home --shell /usr/sbin/nologin rnaseek
sudo chown -R rnaseek:rnaseek /opt/rnaseek
sudo chown -R rnaseek:rnaseek /data/rnaseek

# Reload systemd, enable, and start
sudo systemctl daemon-reload
sudo systemctl enable rnaseek-daphne rnaseek-celery
sudo systemctl start rnaseek-daphne rnaseek-celery

# Check status
sudo systemctl status rnaseek-daphne
sudo systemctl status rnaseek-celery
```

## 16. Session Cleanup Cron

RNAseek sessions expire after 14 days. Expired sessions and their associated files (uploads, intermediates, outputs) must be purged to reclaim disk space.

Create a Django management command or use a cron job:

```bash
# Add to the rnaseek user's crontab
sudo -u rnaseek crontab -e
```

```cron
# Purge expired RNAseek sessions every day at 2:00 AM
0 2 * * * cd /opt/rnaseek && /opt/miniconda3/envs/rnaseek/bin/python manage.py shell -c "
import shutil
from django.utils import timezone
from django.conf import settings
from pipeline.models import Session

expired = Session.objects.filter(expires_at__lte=timezone.now())
count = expired.count()
for s in expired:
    path = settings.MEDIA_ROOT / 'sessions' / str(s.session_id)
    shutil.rmtree(str(path), ignore_errors=True)
    s.delete()
print(f'Purged {count} expired sessions')
" >> /var/log/rnaseek-cleanup.log 2>&1
```

## 17. Firewall

Only expose the ports that Nginx needs:

```bash
sudo ufw allow OpenSSH
sudo ufw allow 'Nginx Full'   # ports 80 + 443
sudo ufw enable
sudo ufw status
```

**Do NOT expose:**
- Port 8099 (Daphne) — Only Nginx should reach it via localhost.
- Port 5432 (PostgreSQL) — Only local connections.
- Port 6379 (Redis) — Only local connections.

## 19. Troubleshooting

### "502 Bad Gateway" from Nginx
Daphne isn't running or crashed. Check:
```bash
sudo systemctl status rnaseek-daphne
sudo journalctl -u rnaseek-daphne -n 50
```

### Static files return 404
Run `python manage.py collectstatic --noinput` and restart Daphne. WhiteNoise caches the manifest at startup.

### WebSocket connection fails
1. Verify the Nginx `location /ws/` block includes `proxy_http_version 1.1` and `Upgrade` headers.
2. Check Daphne logs for WebSocket errors: `sudo journalctl -u rnaseek-daphne | grep -i websocket`

### Celery tasks stuck in PENDING
1. Verify Redis is running: `redis-cli ping`
2. Check Celery is connected: `sudo journalctl -u rnaseek-celery | grep "Connected to"`
3. Verify the task is registered: `celery -A config inspect registered | grep run_core_pipeline`

### "HISAT2 index not found" errors
Reference genomes weren't transferred. Check:
```bash
ls /opt/rnaseek/pipeline/reference_genomes/Human_GRCh38/*.ht2
```

### Permission denied on media directory
```bash
sudo chown -R rnaseek:rnaseek /data/rnaseek/media
sudo chmod -R 755 /data/rnaseek/media
```

### DESeq2 / R errors
Verify R packages are installed within the conda env:
```bash
conda activate rnaseek
Rscript -e "library(DESeq2); cat(as.character(packageVersion('DESeq2')), '\n')"
Rscript -e "library(sva); cat(as.character(packageVersion('sva')), '\n')"
```
